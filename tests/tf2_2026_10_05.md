# TF2 October 5, 2026 networking regression

The Linux TF2 engine snapshot prefix no longer has the leading `m_ListIndex`.
`CFrameSnapshotManager::CreateEmptySnapshot` writes the tick at offset zero,
the entity pointer at 4/8, and the entity count at 8/16 on x86/x86_64.
`SV_ComputeClientPacks` passes the valid-index pointer/count at 12/16 on x86
(24/32 on x86_64). Verify these against the installed engine before deploying
to a different TF2 build; this stub is a partial engine-owned ABI, not a full
allocatable object.

The old x86 stub read `m_pValidEntities` from offset 16: the actual count.
Two crash dumps stopped at the optimizer's `CheckTransmit` index read with
that count, 635 or 238, used as a pointer. The fault was not a changed
`CheckTransmit` function signature.

Run `bash tools/test_snapshot_layout.sh` to check the actual shared stub on
both pointer widths, while preserving the original non-TF2 layout.

Build only the optimize package using `configure.py --sdks=tf2
--targets=x86,x86_64 --optimize-mods-only --enable-optimize
--exclude-mods-debug --exclude-mods-visualize --exclude-vgui` and explicit
SourceMod, Metamod, and SDK paths. Keep deployment backups and replace the
mapped extension atomically. A server restart is required to use the new
binary safely; do not hot-unload the previously incompatible implementation.

## Compiler PIC relocation regression

GCC 14 emits PIC thunks in function replacements. The function copier already
recognized these helpers but did not use that detection. Relocating a call to
`__x86.get_pc_thunk.*` unchanged makes the GOT base relative to the engine
destination, not the extension where its data and function pointers live.
With the new build, this crashed `CEconItemView::GetStaticData` during inventory
validation and `CBaseEdict::GetChangeAccessor` while creating the world entity.
Disabling the corresponding optimizer modules removed these startup crashes.

Rewrite such calls into same-length immediate moves of the original return
address. The following GOT-relative arithmetic then continues to use the
extension's data. Cover all seven possible non-stack compiler registers.

Run `bash tools/test_function_copy.sh`: it compiles and executes relocated
x86 PIC fixtures, separate patch-buffer copies, ordinary external calls, and
x86_64 RIP-relative loads using the production relocation implementation.
